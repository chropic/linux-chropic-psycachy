## Claim-by-claim assessment

- **Installer input identity and TOCTOU — approved; prior finding resolved.** The builder resolves a non-symlink path and records expected size, then `private_installer_snapshot` opens with `O_NOFOLLOW`, checks `lstat`/`fstat` identity, copies bytes to an exclusive `0600` file inside a `0700` temporary directory while hashing, fsyncs file and directory, verifies source size/mtime/ctime/inode stability and snapshot inode/mode/size, and yields only if the copied-byte digest equals the required SHA-256. Both preflight metadata extraction and apply's full installer extraction use `snapshot_iso`; apply also compares its snapshot digest with preflight's `installer_info` and revalidates payload metadata. The context removes the snapshot on both normal exit and errors. The original source path is not used for extraction after snapshot creation. In apply mode the snapshot is under the private `work` directory; the builder checks the existing 24 GiB scratch reserve plus installer size before snapshotting, both before and after work creation. This closes the earlier race absent a privileged attacker who can modify root-owned private work files.
- **Snapshot regression — adequate for the reported replacement race.** The new test creates a snapshot, mutates and then unlinks/replaces the original source, and verifies that metadata extraction invokes xorriso on the snapshot and still reads the original bytes. It checks expected-hash failure and normal context cleanup. It is a small fixture rather than a large ISO test; this is correctly disclosed. It does not directly synchronize a concurrent mutation during the copy loop, but code checks source identity and ctime/mtime/size across that interval and fails closed.
- **Support manifest hash and audit — approved.** `target_support_manifest_sha256` is calculated from the exact generated full target-support path/hash manifest and written to buildinfo. The generated installer script embeds that digest, checks it against `private-support/SHA256SUMS`, verifies each source and destination file hash and containment, regenerates the pinned release initramfs, compares target and ESP initrds, and checks target dpkg status. Final ISO audit checks manifest bytes, every private support file, installer script, and buildinfo replacement bytes.
- **Support source symlink/path safety — approved in code; real tree not exercised.** Git archive is limited to the pinned allowlist and commit. Extraction uses the data filter. The collector rejects symlink directories, non-file/escaping resolved paths and path collisions; internal file symlinks resolve within the extraction root and are copied as bytes rather than links. Four machine files have fixed reviewed paths/hashes and must resolve beneath machine root. Installer payload symlinks are rejected before staging. Generated shell validates manifest rows, source realpath under media and destination realpath under target. The exact private source checkout at the pinned commit and machine files are absent, so only synthetic fixture tests cover this integration. Config marks machine files non-redistributable and buildinfo/status labels private-support output local-testing-only/do-not-publish; the actual private payload cannot be independently inspected here for unusual sensitive content.
- **Installer ISO embedded r2 pin and package pair — approved.** The validation compares embedded pin to selected r2, bundle manifest identity to pin, exact image/headers hashes to both pin and checksum manifests, package metadata and repository copy equality, verification-record package pair, DTB identity, and guarded autoinstall structure. The earlier read-only final51 validation supports the reported ISO/pin/package identities, but it predates snapshot hardening; no snapshot of the 5 GiB ISO was made during this review, as requested.
- **Menu and unattended-install behavior — approved by code review.** The existing Try entry remains before appended install entries and has no `autoinstall`; base behavior is unchanged when installer option is absent. Guarded SP12 install selects generated r2 `casper/vmlinuz`/`initrd` and pinned Surface DTB. Generic diagnostic selects copied stock kernel/initrd paths and has no Surface DTB. Both installer entries explicitly enable `autoinstall`, and config retains all-interactive sections, early exact-device selector and late target installer command. The final audit checks exact GRUB and autoinstall bytes. No generated live ISO was tested.
- **Target support install and initramfs/ESP sync — approved in code.** Support late command follows target kernel installer; it copies all manifest files, reruns the pinned release initramfs generation, checks target initrd existence and byte equality with the ESP initrd, and runs a clean target dpkg audit. Existing boot-sync hooks are installed in the target installer path before this late command. Runtime installer behavior remains unproven without the real inputs/build.
- **Final ISO audit and sidecars — approved with validation boundary.** The build audits exact GRUB, root autoinstall bytes, menu/kernel/DTB policy, replacement hashes, base layers, private support manifest/payload, FDT module, EFI binaries, and physical ESP/NVRAM/mount snapshots. Sidecars are published only after cleanup and include final ISO checksum and buildinfo; full support-manifest SHA is now included in buildinfo. No assembled live ISO or sidecars were produced in this task.
